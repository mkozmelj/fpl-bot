# Security policy

## Reporting a vulnerability

Please report vulnerabilities privately through GitHub's
[private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability):
open the repository's **Security** tab and choose **Report a vulnerability**. Do not open a public
issue, pull request or discussion for a security problem.

Useful in a report: what is affected (file, workflow or bot command), how to reproduce it, and the
impact you expect.

## What to expect

This is a hobby project run for a small invited group. Reports are handled on a best-effort basis:
there is no response-time commitment and no bug bounty. Fixes go through the normal PR pipeline,
and a GitHub security advisory is published when a fix ships if the issue affected users.

## Scope

In scope: the code in this repository, its GitHub Actions workflows and the published container
image. Out of scope: Telegram, the Fantasy Premier League API, Railway, Neon and other third-party
services (report to them directly), and forks run by other people.

## Supported versions

Only the latest commit on `main`, which is what the owner's instance runs.
